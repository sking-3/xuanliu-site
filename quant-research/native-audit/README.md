## Compare

```sh
node quant-research/viprasol-native-parity.mjs native.csv manifest.json candidate.json > parity-report.json
node --test audit/viprasol-native-parity-unit.mjs
```

The tool reads an external CSV and independent candidate. It checks all nine native plotted parameters, minimum tick, daily interval, full calculation seed, ordered timestamps, confirmation status, exact OHLCV and close times before comparing the six required output series. A single trailing unconfirmed candle is reported and excluded; an unconfirmed candle inside history, more than one open candle, missing seed history or another confirmed range rejects comparison. Do not silently discard history to align only the latest suffix: stateful indicators and ATR depend on that history.

Blank/`NaN`/`na` CSV values are unknown, never zero. Boolean events match exactly. Fixed numeric tolerance is absolute `1e-9` or relative `1e-10`, whichever is larger. It is not a tick-sized tolerance. Reports include first divergence, per-field maximum absolute error, divergence count, input rejection reason and ignored open-bar count.

Even a complete numerical match only becomes `matched_pending_native_review` when real evidence files exist. `nativeVerified` and `eligibleForSelection` stay false, and the CLI exits 2. The tool cannot establish authenticity from a provenance string or file existence; the captured source/settings/CSV must first be reviewed against the actual TradingView UI. There is no fabricated native-pass fixture, self-issued production approval or automatic promotion path. This pilot does not connect all 21 indicators or A-share screening.

## Optional Pine Logs

Enable logs only inside the normal personal-script editor when the account permits it. The first calculation bar emits source/symbol/timeframe/exchange-timezone/session/seed metadata and all computational inputs. Each confirmed row emits explicit `time` and `time_close`, raw OHLCV, compression levels, long flag and entry/stop/target with up to 16 decimal places. Log-row field order is exactly that order, after the `AUDIT_ROW|` prefix. `na` is preserved.

Use the log time filters for separate ranges without changing calculation history. Pine Logs retain at most 10,000 historical messages. The historical log prefix is a bar-opening timestamp; realtime prefixes are log-event times. The explicit row times are authoritative. Replay data must be identified as replay, never represented as a contemporaneously discovered current signal. Logs are auxiliary debugging evidence and are not accepted as an exported native CSV by this comparator.
