# 带单员与公开账户研究

本站在 GitHub Pages 的同一个带单员广场展示 Hyperliquid 公开账户和 Binance 跟单组合。来源说明、批次核验统计和汇总提示收纳在底部默认折叠的“资料与统计说明”；卡片和详情中的过期、空仓、不可见与未取得状态仍直接展示。Hyperliquid 名单和表现快照位于 `trader/feed.json`，后台预计算的平仓成交胜率位于 `trader/analytics.json`；Binance 已保存的公开仓位、变化与历史样本位于 `trader/binance/portfolios.json`。个人手工记录仍仅保存在当前浏览器；页面没有文件导入或导出入口。

## 原始身份与卡片布局

卡片和详情保留平台原始标识：Binance 显示组合 ID，OKX 显示带单代码，Hyperliquid 显示钱包地址，不将本站内部记录 ID 误称为平台用户 UID。头像仅来自已确认的来源字段或有公开证据的身份资料；缺失或加载失败时保留文字占位，不合成头像。Binance 从现有详情响应的 `avatarUrl` 保存到 `profile.avatarUrl`，不为头像新增采集请求；旧快照兼容为空。OKX 离线归一化模块保留官方 `portLink` 和 `uniqueCode`，不代表来源已重新接通。

图片使用已核实的 HTTPS CDN 主机并禁止凭据等异常 URL，网页不发送 referrer。熬鹰的公开身份头像来自[币安广场本人主页](https://www.binance.com/zh-CN/square/profile/god_of_trader_tony)，[Kopyon 文档](https://kopyon.com/binance-copy-trading-api/)中的相同组合 ID、昵称和图片路径用于交叉核对；这不产生交易采集时间或解除任何采集停止状态。

混合名单统一身份、周期、状态与收益区域的顺序，同排卡片拉齐；币安的完整样本数量和较长说明保留在详情中。缺失、过期和统计口径仍在卡片可见，不以虚构曲线填充空白。

## 已接入来源与范围

Hyperliquid 官方网页使用 `https://stats-data.hyperliquid.xyz/Mainnet/leaderboard` 获取公开账户列表。首次验证收到 48,229 个账户的有效 JSON；每次采集先选取来源月度盈亏最高的最多 200 个候选，再逐一核验默认永续 DEX 的持仓。每轮 Hyperliquid 成功采集的名单只选入核验到非零持仓的账户；空仓、请求失败及未核验账户不新加入该轮名单，也不向更低排名补足 200 个。前台会保留已保存名单中的历史卡片，不因核验到期或本页读到空仓而隐藏；它不是无限期历史档案，新一轮有效名单仍以本次筛选范围为准。筛选、排序只作用于本次核验后保留的账户，不代表完整交易所名单、认证带单员或投资推荐。名单可能包括普通钱包、金库及其他账户；展示名由账户自行设置，不是实名或身份认证。

- 周度、月度、累计的 ROI 和 PnL 直接采用来源对应 `week` / `month` / `allTime` 字段。ROI 小数乘 100 显示为百分比，金额口径为来源 USD。
- 季度、半年、年度从 `perpAllTime` 的真实配对采样截取，并查询公开非资金费流水，逐段核对权益变化与盈亏、资金流。通过核验后自动保存“自算收益率”，首页与广场共用结果；未通过时保存具体缺失原因。实际覆盖区间可能短于所选天数，不插值补齐。
- `7D` / `30D` 是本站兼容键；页面将这类源端窗口显示为“周度（来源）”和“月度（来源）”，不擅自承诺精确起止时刻。
- 账户权益直接采用 `accountValue`；零值不被视为缺失。
- 榜单快照中的回撤、胜率、曲线保持空值。回撤和曲线由浏览器按需读取官方 `portfolio` 数据；平仓成交胜率由后台采集并保存到独立的 `analytics.json`。没有充分输入的指标保持空值，不用示例值填补。
- `fetchedAt` 是采集时间；`snapshotAt` 是 HTTP Last-Modified 表示的来源文件时间，不是每个账户自身最后成交或更新时刻。

`binance-data.js` 只解析本站已保存的 JSON，不请求交易所。身份、来源链接、完整快照和批次停止状态严格验证。有效持仓要求公开可见、成功完整快照、源采集与快照时间均未超过原有 30 分钟期限，且当前读取成功、账户和批次均未停止。明确空仓为 0，未知或过期为 null；历史仓位保留原核验时间，不伪装成当前仓位。

详情中的仓位变化是前后快照差异，不能当作逐笔成交。订单与历史持仓只是来源分页样本，保留两个订单时间和覆盖信息，始终标记历史不完整；没有可靠订单 ID 的相似行不擅自去重。缺少来源指标时 ROI、回撤、胜率留空，不从少量样本伪造完整业绩。隐藏或未知可见性的交易内容不展示，停止账户不重试。

旧 `/trader/binance/` 页面只做兼容跳转，进入广场的 Binance 筛选；已注册的组合 ID 会转换成同页搜索。未知、空值或重复 ID 不自动跳转到另一个账号。

### Binance 30D 来源业绩

独立保存 `performance.byPeriod["30D"]`，四项为来源直接返回的 ROI、PnL、MDD 和胜率，不由最多 20 条历史样本推算。精确请求为公开网页接口 `GET /bapi/futures/v1/public/future/copy-trade/lead-portfolio/performance?portfolioId=…&timeRange=30D`；仅在原三账号的身份、公开状态、ACTIVE 状态与既有停止守卫通过后请求。熬鹰资本身份卡不参与采集。

ROI、MDD、胜率按来源百分数保存，不再乘 100；PnL 计价为 USDT。数据为独立的 30D 请求周期，缺少其他周期时显示未取得，不拿 30D 代替 7D、90D、180D、365D 或累计。未取得收益曲线时不生成模拟走势。单项缺失保留 null，来源明确返回 0 才显示 0。

依据[币安业绩说明](https://www.binance.com/en/support/faq/detail/54aa6d3b43bc4f6eb4a3a6e3aea40acd)，PnL 包括已实现和未实现部分，组合层面的已实现部分扣除相关费用；现行 ROI 使用最大资金基数。胜率按来源仓位口径，部分平仓不作为完整平仓计数，与 Hyperliquid 的平仓成交片段胜率不同。页面保留各平台指标名称与口径，不暗示两者统计方式相同。

绩效有独立的最近尝试、成功采集时间和证据摘要；来源未提供更新时间时 `sourceAsOf` 保持 null。成功采集绩效不会刷新仓位核验时间；页面超过 60 分钟将旧绩效标旧。失败保留原成功值与原时间，隐藏状态清除交易和绩效内容，停止规则保持有效。新集合或新仓位不能掩盖同周期绩效时间回退。

### Binance 30D 盈亏曲线

曲线独立保存于 `chart.byPeriod["30D"]`；请求 `GET /bapi/futures/v1/public/future/copy-trade/lead-portfolio/chart-data?portfolioId=…&timeRange=30D&dataType=PNL`。仅原三个获准公开组合通过既有停止与可见性检查后采集。依据[公开请求实现](https://github.com/doppelganger237/gendan/blob/7e8dd5bd195798f9af61dfcd265178f1500cf3d1/copy_trade_api/futures.py#L122)与[图表字段用法](https://github.com/doppelganger237/gendan/blob/7e8dd5bd195798f9af61dfcd265178f1500cf3d1/reports/image_report.py#L999)，将 `dateTime` 毫秒转换为 UTC 时间，`value` 直接保存为 USDT。不乘 100、不减去首点、不累计、不补造采样点；它不是 ROI 百分比曲线，也不是逐笔成交轨迹。

最多接受 1000 个有效点，拒绝重复时间、非有限数值和超过接收时间 5 分钟的未来点。少于两个点不绘制曲线，其他周期不借用 30D 数据。卡片与详情分别注明曲线单位、成功采集时间及实际点列的起止范围；30D 为请求窗口，不保证每一天都有样本或末点就是当前时刻。来源未提供更新时间，`sourceAsOf` 保持 null。

曲线有独立的尝试、成功时间与响应摘要，超过 60 分钟或读取失败标旧；失败保留原成功点列及时间，旧或非法曲线不能覆盖较新的已验证样本。成功曲线不会续期仓位或绩效，不解除账号或批次停止；未知与隐藏状态清空交易曲线。浏览器只读取本站快照，不直连币安补采。

## 更新与失败处理

`.github/workflows/refresh-traders.yml` 将持仓核验计划改为每小时第 11、26、41、56 分钟（每 15 分钟一次），另在 UTC 每日 00:12、06:12、12:12、18:12 计划执行完整分析（`12 */6 * * *`）。两种模式共用同一 `pages` 并发锁，避免采集预算和提交竞争；持仓模式跳过耗时分析，保留分析文件及其原采集时间，完整模式在分析完成后再次核验持仓。该拆分用于降低长分析批次对常规持仓更新的阻塞，不能保证任务按时执行。并发组使用 `queue: max` 保留最多 100 个等待任务，避免排队的完整分析被后到持仓任务替换；队列满时新增任务仍可能取消，六小时完整分析是计划而非完成承诺（[GitHub 并发说明](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/control-workflow-concurrency)）。主分支推送和手动触发仍可使用；`[ui-only]` 在事件提交与实际检出的 main 一致时跳过全部 Hyperliquid 与 Binance 采集，仅测试并部署现有快照；若 main 已变化，则在来源请求前停止，不转为完整采集。`[positions-only]` 即使排队期间主分支已前进，也继续选择持仓模式，不再意外升级为耗时完整分析；普通延迟推送保留完整模式。旧 `27,57 * * * *` 定时事件仍可按持仓模式处理，以兼容修改前已投递的事件。所有采集模式继续执行原有来源停止检查，不因仅界面发布清除停止状态。

**调度修复与验收。** 2026-11-10 北京时间 22:02 核对时，两类快照仍停在 20:30–20:33；默认分支、非 fork、近期仓库活动和 cron 与解析器的一致性已核实，尚不能仅据停更认定唯一原因。此次同步修改 cron 及解析器，并修复延迟仓位推送被升级为完整分析的问题。每 15 分钟的计划给 Binance 30 分钟持仓有效期预留采集和发布时间，未延长数据有效期。GitHub 官方说明调度可能延迟或丢弃；关联 actor 异常时，具有写权限的用户修改 cron 可以恢复关联（[故障说明](https://docs.github.com/en/actions/how-tos/troubleshoot-workflows)）。因此必须用自然 `schedule` 运行及其实际快照验收，不能将推送或手动成功当作定时持续恢复。

`schedule-health.yml` 保留每小时第 26、56 分钟的独立诊断计划，只打印事件、actor 和时间，不检出代码、不请求来源、不写仓库、不发布。实际更新以每次运行结果和各账户真实采集时间为准；静态 Pages 页面上的“刷新”不能启动后台采集。这不是实时成交行情。

前台“刷新”只重读本站快照，不重载已打开的 HTML 与 JavaScript。发布后旧标签页可能继续用旧界面读取新数据；浏览器重新加载页面或打开带版本参数的入口后才加载新的页面代码。当前没有可供该按钮安全调用的后端调度接口，不能启动 GitHub 采集任务；不得向网页放置 GitHub token。外部调度服务或自有服务器尚未接入。

后台在任意 Hyperliquid 采集之前读取上次保存的 `feed.json`、`portfolios.json` 和 `analytics.json`。其中任一来源或账户状态记录 `http_403` / `http_429` 时，整轮跳过 Hyperliquid 请求，保留停止记录及原数据时间；切换 `positions` / `full` 或重新运行不会自动解除停止。状态文件缺失、超限或无法验证则在请求前失败，后续恢复必须另行核实，不能靠自动重试清除拒绝。Binance 的原有独立守卫保持不变。

页面可见时每分钟检查本站小型快照，隐藏时暂停。采集失败保留已通过验证的数据及原时间，并标记过期。Hyperliquid 持仓资格超过 60 分钟后不再计为有效持仓，但保留账户与已有历史，卡片明确写明最后核验时间和当前持仓未知；旧版未经持仓核验的名单仍不展示。持仓资格只代表核验时刻，不保证此后没有平仓。详情成功读到更新的空仓时更新资格和空仓说明，保留该卡片；读取失败不冒充空仓。首次读取失败且没有有效快照时展示不可用，不制造记录。Binance 仍使用独立的 30 分钟期限，未延长任何来源的有效期。

采集器先发一次有大小与时间限制的 HTTPS GET，再对最多 200 个候选各发一次只读 `clearinghouseState` POST。持仓请求最多并发 4 个、每秒启动 2 个、单次最多 10 秒、整批最多 240 秒。403/429 立即停止整批，不自动重试；非 JSON、异常结构、过旧持仓时间均视为核验失败。持仓核验时间与榜单文件时间分别保留。成功但无仓位与请求失败分别计数。不使用密钥、代理池、客户端伪装或绕过限制。39 MB 的原始来源文件仅用于云端核验，不发布进仓库或网页。公开文件仅包含选中账户的必要字段。

## 按需持仓、挂单与成交

公开 Hyperliquid 账户详情新增“实时交易”视图。只有打开该视图才向官方 `https://api.hyperliquid.xyz/info` 请求 `clearinghouseState`、`frontendOpenOrders` 和 `userFills`，并连接 `wss://api.hyperliquid.xyz/ws` 订阅该地址的 `userFills` 与 `orderUpdates`。公开名单加载不会为200个账户同时建立连接；个人手工记录不会被自动发送到来源。

持仓、挂单是 REST 状态快照，页面打开期间约每60秒核对一次；成交和订单事件通过 WebSocket 接收。实时流不可用但 REST 可读时，最近成交退回每60秒快照查询，页面明确显示降级状态。首次 `isSnapshot` 是此前成交记录，不能当作新开仓。A表示卖、B表示买，开仓/平仓直接采用来源 `dir`；成交金额为价格乘数量的名义金额，不是保证金。手续费保留来源币种，负数可能是返佣。现货代码通过官方 `spotMeta` 解析，缺少映射时显示原始代码，不猜报价币。

REST 成交接口最多返回最近2000笔，本页面保留最近200笔用于阅读，不宣称完整历史。记录按成交标识去重，不用短暂静默判断订单全部成交。当前永续持仓仅覆盖默认永续DEX，挂单覆盖默认DEX及其返回的现货订单；其他DEX覆盖不被暗示为完整。

关闭详情、切换标签/账户或隐藏页面时停止连接；返回页面后重新读取状态。错误/断开会在详情中显示，旧数据与读取时间保留。本功能不在关闭页面后继续监听，不是全天后台档案，也不含任何下单、授权、签名或交易密钥。

## 卡片曲线与风险指标

`account-analytics.js` 保留只读的浏览器曲线分析。页面打开后，仅为当前页最多 12 张仍具有效持仓资格的 Hyperliquid 公开账户卡片自动读取 `portfolio`；保留的过期历史卡片和 Binance 组合不会因此进入该自动请求队列，Binance 也不会进入 Hyperliquid 实时客户端；翻页取消已离开页面账户的请求，隐藏页面暂停读取。曲线结果仅内存缓存 5 分钟，最多并发 2 个，滚动一分钟最多使用 400 请求权重。403/429 后停止自动读取，曲线错误重试需显式操作。分析结果与榜单 ROI/PnL 的采样时间分开，不改写来源发布的收益率。

普通卡片和分析详情不再由浏览器请求 `userFills` 来计算胜率，而是读取同源的 `analytics.json`。页面可见时约每 60 秒检查新快照；重复刷新只读取聚合文件，不为每位访客重复采集成交。读取失败时保留本页已取得的成功结果及原时间并标陈旧；尚无有效结果则显示空值。只有主动打开“实时交易”视图时，仍按上一节读取实时交易数据。

## 长周期收益率自动计算

`period-roi.js` 使用 `100 × 区间盈亏 / max(100 USD, 期初权益 + 区间最大累计净入金)`。这是本站依公开流水计算的资金基数口径，不是 TWR，也不是来源直接发布的季度或年度值。资金路径包含采样点之间的入金再出金，不能只用净变化猜测资金峰值。每段权益与盈亏必须同时间戳配对，和已识别资金流的绝对差不超过 0.02 USD。未知流水、无法辨别先后的同时资金事件、分页截断、无法对账均不产生新百分比。

采集仍由既有完整分析任务执行，portfolio 与资金流水共用每分钟 600 权重、并发 2、单批 7 分钟预算；每个流水请求预留 120 权重，每户总计最多 10 页、20,000 条，重叠时间游标去重。先核验季度，再向前补半年与年度，复用已取得的后段；长段普通失败不会抹掉本轮已核验短段。预算只能覆盖一部分账户，按真实采集/尝试时间轮换，不能承诺一次补齐全榜。403/429 停止整批且不重试。只发布聚合证据与实际时间，不发布原始流水。公开 API 不保证历史保留完整，查询结束只表示本次可返回数据已遍历，证据始终保留 `historyComplete: false`。

浏览器只读取持久结果；新的前台曲线如果没有对应资金流水证据，不能覆盖已核验收益率所绑定的整份旧窗口。旧结果继续标注旧采样，绝不将旧 ROI 与新 PnL、区间或采集时间拼接。公式、资金基数、实际范围、流水采集时间与缺值原因可从指标说明查看。

## 后台胜率预计算与持久缓存

`scripts/collect_trader_analytics.cjs` 在名单和持仓核验后运行，对本轮合格账户请求官方 `userFills`，复用 `account-analytics.js` 的同一胜率归一化函数。它保存最近最多 2000 条成交所得的聚合统计，不保存或公开原始成交流水，也不请求交易密钥或下单权限。

- 完整分析计划每 6 小时执行；每轮最多 200 个已核验账户，优先采集没有成功结果或成功结果最旧的账户。成交统计 20 分钟、portfolio 30 分钟内仍有效的成功结果可复用；六小时后的批次通常需要重新采集，200 个账户仍可能受单批预算限制而分轮完成。
- 后台使用滚动一分钟 900 权重预算，每次成交请求按最坏 120 权重预留，最多并发 2 个，单次请求（含响应体）最多 12 秒，单批最多 22 分钟。900 是本站保守预算，不是交易所的官方硬上限。
- 达到批次期限后保留已完成结果及上次有效缓存，未完成账户在下一轮优先。134 个冷缓存账户通常需要约 19 分钟加网络耗时；200 个账户可能跨轮补齐，不能承诺每 30 分钟完整更新全部账户。
- 任何 403/429 均停止剩余队列并取消在途请求，不自动重试。如果前面的持仓核验步骤已遇到 403/429，胜率步骤直接跳过；不通过代理或客户端伪装继续访问。
- 成功结果、样本数量和时间写入 `trader/analytics.json` 并随网站持久提交。采集失败保留该账户上次有效结果和原 `fetchedAt`，错误及最近尝试时间独立记录。无有效缓存则保留 `null`；无平仓样本是成功取得的空统计，不是 0% 胜率。
- `generatedAt` 是聚合文件生成时间，账户 `fetchedAt` 是该账户统计采集时间，`lastAttemptAt` 是最近请求开始时间，样本起止时间来自成交记录。文件更新不能代替账户数据更新，采集时间也不能冒充成交时间。
- 卡片显示平仓样本数和采集时间，详情展示完整样本范围及统计口径。超过 60 分钟、最近采集失败或当前快照读取失败的旧结果明确标陈旧；保留 `historyComplete: false` 和是否触及 2000 条上限。
- 完整分析的 `feed.json`、`analytics.json` 和 `portfolios.json` 随同一提交发布；持仓模式保留两份分析文件原内容与原时间。两份分析结果仍在采集后 60 分钟标记陈旧，六小时计划没有延长此期限；当前页仍具有效持仓资格的 Hyperliquid 账户缺失或陈旧的 portfolio 仍可能触发既有浏览器按需读取，胜率不会由浏览器补采成交。任务在提交前检查主分支是否变化，正常推送拒绝并发改动；部署前再次核对提交。不会强推、覆盖新改动，失败也不会用合成测试数据填补。

后台冷启动会增加本次部署等待；持仓核验时间不会因胜率采集而重写。浏览器仍独立执行 60 分钟持仓资格期限，因此长任务或定时任务停止时不会把过期核验当作当前持仓。

## 指标口径

- **Hyperliquid 曲线**：使用来源 `week/month/allTime` 的真实 `pnlHistory` 点，以窗口首点为零基准。必要时只从原始样本选点，不虚构中间波动、不用账户余额变化代替盈亏。回撤先用完整原始样本计算，再为迷你图选点。
- **来源采样回撤**：核验官方前端计算后采用 `max((历史累计盈亏峰值－当前累计盈亏)/峰值时账户权益) × 100%`。累计盈亏创新高或持平时更新该峰值时的权益分母。要求盈亏与权益数组逐点时间相同、数值有限且分母有效。来源样本不足则留空。它是来源采样口径，可能超过 100%，并非完整盘中或资金流调整后策略净值回撤；不除以累计盈利峰值，不擅自截断到 100%。
- **平仓成交胜率**：从最近最多 2000 条成交中，筛选默认永续、USDC 手续费、合法方向和数量的 `Close Long/Close Short` 成交；`closedPnl - fee > 0` 的笔数除以全部有效平仓成交。零毛盈利扣费后亏损也计入；净盈亏为零保留在分母。负手续费返佣按原符号处理。反手、现货及其他 DEX 不混入。
- 胜率展示实际样本起止时间与笔数，独立于卡片所选收益窗口。分笔成交分别计数，只扣本次平仓手续费，未分摊开仓手续费和资金费；因此不是完整交易轮回胜率，也不承诺覆盖整月或累计历史。零有效样本则留空。

卡片使用“万／亿”压缩大额数字，完整数值通过提示及详情保留。绿表示盈利、红表示亏损。没有交易密钥、交易权限或自动跟单行为。
