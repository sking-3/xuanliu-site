# 币安公开带单组合试接入

本模块展示 Copy Trading 公开组合 5156287639231681792，上游昵称为“爱喝快乐肥宅水”。没有将它当作熬鹰本人，也不把传统 portfolioId 当成 Smart Money topTraderId。

## 数据与运行

- scripts/collect_binance.cjs 是独立编写的只读采集器，不调用 Apify，不需要币安密钥、Cookie 或登录。
- 先校验详情身份、ACTIVE 状态和 positionShow，再读取当前仓位、最近7天订单第一页、历史仓位第一页。两种历史各最多20条，始终标记 complete:false，不宣称完整交割单。
- 零数量条目被过滤。缺失、重复仓位键、非JSON和业务失败不视为空仓；保留最后成功快照及其时间。明确关闭仓位公开时清除新发布文件中的旧仓位、观察和历史，仅保留受限状态及过去成功的时间；仓库的既往历史版本不能因此撤回。单向BOTH仓位按原数量正负保留真实多空方向。
- HTTP 202/401/403/418/429/451、非成功业务码、隐藏、身份不符或结构变化会持久停止自动刷新。修复原因并人工审查后才可解除 refreshStopped；不得通过代理、凭据替换等绕过限制。
- 请求依次进行，间隔至少2秒，单次15秒上限、响应2MB上限，无自动重试。只有允许的固定组合和固定上游地址可被查询。
- 快照中只发布必要展示字段与响应SHA-256，不发布上游用户内部标识等无关资料。最多保留24份成功快照、200个观察事件。
- 第一次成功或长时间中断后建立基线；两个完整成功快照才可比较数量。连续两次未见原仓位才记录“观察到归零”。不推造成交价、成交时间、手续费或资金费。
- 订单接口未提供稳定订单ID。样本按来源页面保留，字段完全相同的两行也不擅自合并；跨轮替换当前样本，尚不支持无漏无重的完整历史档案。
- source.lastSuccessAt/snapshot.observedAt 是采集完成时间，不是币安最后更新时刻。未取得可靠上游仓位更新时间；前端超过30分钟自动标旧。

页面只请求本站 snapshot.json，访客不会直接访问币安。浏览器每5分钟检查已发布JSON，隐藏页面暂停；这不是后台采集频率，更不代表币安实时推送。

## 发布与维护

沿用现有 Refresh trader data and deploy Pages 工作流；当前主站定时配置为每小时27、57分钟，GitHub可能延迟，Hyperliquid前序任务也会影响实际发布时刻。每次采集结果和整站同一提交部署，不覆盖既有Hyperliquid数据。定时运行是否正常应以Actions实际记录为准。

测试：
- node audit/binance-collector-unit.cjs
- node audit/binance-ui-unit.cjs

首次线上测试必须核对：实际workflow、同一提交的网页与snapshot、数据状态、身份、数量和更新时间。成功启动任务不等于成功取得数据。

来源入口：https://www.binance.com/en/copy-trading/lead-details/5156287639231681792

并发保护：采集前核验同一工作流上次实际执行该采集步骤的运行是否整体成功。若提交/发布未确认成功、有限历史内无法确认、或重跑同一次任务，则不请求币安，写入需人工核查的停止状态；GitHub元数据查询失败也不请求。这样即使main并发变动导致新停止标志未能提交，下一轮也不会自动重新访问来源。
